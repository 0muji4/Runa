# PRD: きょうの一曲を実在の楽曲の紹介と試聴にする

Status: Finalized

## 背景と課題

きょうの一曲を、運営者が Apple の楽曲カタログから選んだ実在の楽曲の「紹介と 30 秒の試聴」にする。

Runa は夜に寄り添う日記アプリで、ホームの三つの静かな時間の一つとして「きょうの一曲」を持つ。現在、きょうの一曲は運営者が日ごとに登録した曲を、アプリ内のプレイヤーで再生・一時停止・シークできる画面（07 きょうの一曲）と、過去の曲を一覧する画面（08 これまでの一曲）で提供している。登録する内容は曲名・アーティスト名・アートワークの URL・音源の URL で、音源は運営者が用意したものを Runa のサーバーから配信する前提になっている。

この前提では、実在のアーティストの楽曲を載せられない。音源を自分で配信するには、楽曲の著作権（JASRAC / NexTone）に加えて、録音物の権利である原盤権のライセンスをレーベルごとに得る必要があり、個人が運営する Runa の規模では現実的でないためである。ユーザーのサブスクリプション経由でフル再生する方法（Apple Music の MusicKit や Spotify の SDK）もあるが、加入していないユーザーには何も再生できず、加入状態の取得と各 OS の SDK 導入を伴うので、最初の一歩としては大きい。

一方、Apple は iTunes Search API を通じて、楽曲の 30 秒プレビュー・アートワーク・Apple Music へのリンクを、**その楽曲を宣伝する目的に限って**無償で提供している（[iTunes Search API: Overview](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/index.html) の Legal 節、2017-09-19 版）。この条件の内側に収まる形にきょうの一曲を作り替えれば、実在の楽曲を載せられる。Apple の条件は次の六点である。

1. プレビューとアートワークは、その楽曲を宣伝する画面にだけ置く。
2. Apple が承認したストアバッジに隣接させ、バッジはその楽曲の Apple Music / iTunes のページへ直接リンクする。
3. プレビューを含む場合、"provided courtesy of iTunes" の帰属表示を置く。
4. プレビューはストリーミングのみで、ダウンロード・保存・キャッシュをしない。
5. 宣伝目的から独立した娯楽価値として使わない。
6. 他の商品・サービスの宣伝に使わない。

現在の 07 画面は、シークバーを持つプレイヤーとして音源そのものを聴かせる作りなので、5 の「独立した娯楽価値」に読まれる余地がある。そこで、画面の主役を「この曲を Apple Music で聴く」という紹介に置き換え、30 秒の試聴はその紹介を補うものとして置く。

## 要件

### Step 1: 運営者は Apple のカタログの楽曲を、日付に対して登録できる

運営者は、Apple のカタログ上の楽曲を一意に指す識別子と日付だけで、その日のきょうの一曲を登録できる。曲名・アーティスト名・アートワーク・試聴・Apple Music へのリンクは、登録した識別子から Runa が取得し、運営者が個別に入力しない。

登録時点でその楽曲が Apple の日本のカタログに存在しないか、試聴が提供されていない場合、登録は失敗し、運営者にその理由が返る。

現在登録済みの曲（運営者が用意した音源）は、この変更でいったんすべて消え、運営者が Apple のカタログの曲で登録し直す。

### Step 2: 利用者は 07 きょうの一曲で、楽曲の紹介を見て試聴できる

利用者は 07 きょうの一曲で次を見られる。

- アートワーク（07 の現在の大きさで、ぼやけずに表示できる解像度）、曲名、アーティスト名
- その楽曲の Apple Music のページを開くバッジ（画面の主となる操作）
- 30 秒の試聴の再生と一時停止、および試聴の進み具合（シークはしない。試聴をプレイヤーの体験に寄せず、紹介の補助にとどめるため）
- 試聴が 30 秒のプレビューであることの表示
- "provided courtesy of iTunes" の帰属表示

試聴は、利用者が再生を押したときだけ始まる。

### Step 3: 利用者は 08 これまでの一曲で、過去の紹介を一覧できる

利用者は 08 これまでの一曲で、過去のきょうの一曲を新しい順に一覧し、各曲について Step 2 と同じ紹介と試聴を得られる。再生の記録（利用者がいつどの曲を試聴したか）は現在と同じく残る。

### 非機能要件

- N1（表示義務）: アートワークまたは試聴を表示するすべての画面に、その楽曲へのバッジと帰属表示を同じ画面に置く。曲名とアーティスト名だけを文字で示す場面（たとえば将来ホームに曲名を出す場合）は、この義務の対象外である。
- N2（ストリーミングのみ）: 試聴の音声は Runa のサーバーにもクライアントにも保存・キャッシュしない。アートワークとメタデータ（曲名・アーティスト名・各 URL）は保存してよい。
- N3（Apple の応答に依存しない可用性）: Apple の API が応答しない、または遅いときも、登録済みのきょうの一曲とこれまでの一曲は直近に取得した内容で表示できる。ホームがオフラインで動く現在の性質は保つ。
- N4（Apple の API の利用量）: Apple の API への問い合わせは、Apple が案内する目安（およそ 20 回/分）を超えない。利用者の数に比例して問い合わせが増えない。

## 責務の境界

楽曲の音源・アートワーク・メタデータの権利は Apple と権利者にあり、Runa は上記の Apple の条件の内側でそれらを表示する。Runa が権利者と直接契約することはない。

## リスクと前提条件

前提条件:

- iTunes Search API の Legal 節（2017-09-19 版）が、この PRD の実装時点でも有効であること。実装前に運営者が当該ページの現行文言を確認する。
- 載せたい楽曲が Apple の日本のカタログに、試聴付きで存在すること。存在しない楽曲は Step 1 の登録で失敗として検出される。

リスク:

- Apple が、Runa の使い方を「宣伝目的から独立した娯楽価値」と判断する可能性。Runa はバッジを画面の主とし、試聴を補助に置くことでこの読みを避けるが、最終的な判断は Apple にある。運営者は Apple から削除要請があれば直ちに応じる（Apple の条件が求めている）。
- Apple が iTunes Search API を廃止または変更する可能性。変更時に直す範囲を Runa の一箇所にとどめる設計は DD が扱う。

## 今後扱う範囲（別ドキュメント）

- Apple Music 加入者向けのフル再生（MusicKit）。今回の紹介と試聴は、加入していない利用者への表示として残る。
- ホーム（06）にきょうの一曲の曲名を出すこと。出す場合は N1 の対象外の範囲（文字のみ）で行う。
- iTunes アフィリエイトプログラムへの参加。
